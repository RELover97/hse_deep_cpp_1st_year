# Перегрузка функций и операторов: результаты учебных тестов

## Постановка задачи

Представим, что преподаватель проводит три небольших теста. За каждый тест студент получает некоторое количество баллов — целое число. Мы хотим написать простую консольную программу, которая умеет работать с этими результатами: хранить три числа для одного студента, изменять отдельный результат, вычислять сумму баллов и выводить оценки на экран. Позже программа должна хранить результаты нескольких студентов, чтобы по идентификатору можно было найти нужную запись.

Студенты учатся в группах, а внутри каждой группы имеют порядковые номера. Поэтому одного номера недостаточно: студент № 1 есть и в группе A, и в группе B. Для каждой записи понадобятся два связанных понятия: `Scores` — результаты трёх тестов, и `StudentId` — пара из названия группы и номера студента. Например, наши условные данные могут выглядеть так:

```text
Группа A, студент 1: 1, 3, 5 баллов — всего 9
Группа A, студент 2: 5, 5, 5 баллов — всего 15
Группа B, студент 1: 2, 3, 4 балла — всего 9
```

Мы хотим уметь получать результат студента по паре (группа, номер), просматривать записи в определённом порядке, находить количество наборов баллов, удовлетворяющих заданному порогу, и выводить данные в понятном формате. Мы также хотим складывать два набора результатов поэлементно и умножать все три числа на коэффициент.

## Класс `Scores`

Нам нужно хранить три результата одного студента и уметь получать их сумму. Для этого создадим класс `Scores`: его конструктор принимает три целых числа, а метод `total()` возвращает сумму.

Сразу разделим объявление и реализацию. В `scores.hpp` виден публичный интерфейс `Scores`, а в `scores.cpp` находится код методов. `CMakeLists.txt` собирает `main.cpp` и `scores.cpp` в один исполняемый файл с использованием C++17.

## Один интерфейс `print` для разных типов

Сейчас результат выводится напрямую из `main.cpp`. По мере развития программы нам понадобится печатать не только оценки, но и обычные числа. Необязательно придумывать имена `printInt`, `printDouble` и `printScores`: в C++ можно объявить несколько функций `print`, различающихся параметрами. Добавим в `main.cpp` версии `print(int)`, `print(double)` и `print(const Scores&)`, а затем вызовем их с аргументами соответствующих типов.

Компилятор определяет подходящую перегрузку при компиляции, исходя из аргументов вызова; это не виртуальный вызов и не выбор во время выполнения. Функции `print` размещены в безымянном пространстве имён: они нужны только внутри `main.cpp`. Важно, что разные возвращаемые типы сами по себе не создают разных перегрузок — выбор функции определяется её параметрами.

Посмотрев символы в объектном файле, можно убедиться, что аргументы функций кодируются вместе с их именами (mangling):
```
cmake -B build -S .
cmake --build build
nm build/CMakeFiles/scores.dir/main.cpp.o
nm -C build/CMakeFiles/scores.dir/main.cpp.o
```

## Как компилятор выбирает перегрузку

В простых вызовах `print(7)` и `print(2.5)` тип аргумента точно совпадал с одним из параметров. Теперь попробуем передать `short` и `float`. Мы не добавляем для них новые `print`: компилятор может преобразовать `short` к `int`, а `float` к `double`. В наших примерах это продвижения типов (promotions), которые имеют более высокий приоритет, чем обычные стандартные преобразования.

Но подходящая функция не всегда бывает единственной. Создадим `choose(long)` и `choose(double)`. Для аргумента `42` типа `int` обе функции жизнеспособны, однако преобразования `int → long` и `int → double` имеют одинаковый ранг. Поэтому `choose(42)` не скомпилируется: компилятор не должен угадывать наше намерение. Мы оставим этот вызов в комментарии, а рабочие примеры запишем с `static_cast<long>(42)` и `static_cast<double>(42)`. При чтении этих строк полезно помнить, что возвращаемый тип функции не разрешает неоднозначность; `using Number = int` не создаёт нового типа, а верхнеуровневый `const` у параметра, передаваемого по значению, также не создаёт отдельную перегрузку.


## Делаем доступ к отдельному результату удобнее

До сих пор `Scores` позволял получить лишь общую сумму. Если после проверки теста нужно исправить один результат, хотелось бы написать `first[1] = 8`, как при работе с массивом. Для этого добавим в класс `operator[]`. В отличие от обычной функции, такой оператор позволяет использовать синтаксис индексации, однако определять `operator[]` разрешено только как метод класса.

Одной версии оператора недостаточно. Неконстантному объекту нужна функция, возвращающая `int&`: ссылка позволяет присвоить новое значение элементу. Для `const Scores` введём отдельную перегрузку с `const` после списка параметров, возвращающую `const int&`, чтобы чтение оставалось возможным, а изменение через полученную ссылку — нет.

## Складываем результаты, не дублируя логику

Следующая естественная операция — сложить результаты двух объектов `Scores` поэлементно. При этом нужно различать две ситуации: `first += second` должен изменить `first`, а выражение `first + second` — вернуть новый объект, не меняя аргументы. Начнём с метода `operator+=`, который прибавляет элементы другого объекта к закрытому массиву и возвращает `Scores&`.

Теперь реализация бинарного `operator+` становится короткой: свободная функция получает левый операнд по значению, вызывает для этой копии `+=` и возвращает её. Вся арифметика остаётся в одном месте; если способ сложения изменится, не придётся исправлять два независимых алгоритма. Обратите внимание на различие возвращаемых типов: в `+=` выражение `return *this;` безопасно возвращает ссылку на существующий объект и позволяет писать цепочки присваиваний. А результат `+` нужно вернуть по значению: ссылка на его локальную копию после выхода из функции стала бы висячей.
