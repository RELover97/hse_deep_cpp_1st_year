# Рассадка гостей: шаблоны в C++

Представим, что мы собираем друзей на домашний ужин. Нужно знать, кто приглашён, какие места за столом заняты и кто где сидит. Позже понадобится отвечать на вопросы в обе стороны: «На каком месте Аня?» и «Кто сидит на месте № 5?», а также отмечать, кто подтвердил участие.


## 1. Проверка гостя и места

Начнём с двух списков:

```cpp
const std::vector<std::string> guests = {"Аня", "Илья", "Маша"};
const std::vector<int> occupiedSeats = {2, 5};
```

`std::vector<T>` — стандартный контейнер, хранящий последовательность элементов типа `T`. В первом случае элементы — строки, во втором — целые числа.

В `src/main.cpp` есть функции `isInvited` и `isSeatTaken`. Первая проходит по именам и сравнивает очередное имя с искомым; вторая точно так же проходит по номерам мест. Обе возвращают `true`, если нашли совпадение, и `false`, если просмотрели весь список.

Внимательно сравним их *действия*: отличны только тип элемента и тип искомого значения, а сам алгоритм поиска в обоих случаях одинаков.

## 2. Одно действие для разных типов: шаблоны функций

Вместо двух отдельных функций поиска мы хотим написать *один алгоритм*, работающий и со строками, и с числами. Переписывать тела при добавлении нового типа неудобно: исправление ошибки пришлось бы повторять в каждой копии.

В `include/algorithms.hpp` теперь находится:

```cpp
template <typename T>
bool contains(const std::vector<T>& values, const T& wanted) {
    for (const T& value : values) {
        if (value == wanted) {
            return true;
        }
    }
    return false;
}
```

`template <typename T>` объявляет **параметр шаблона** — обозначение типа, который пока неизвестен. Внутри функции `T` используется в трёх местах: тип элементов контейнера, тип искомого значения и тип переменной цикла. Само по себе это описание — ещё не отдельная функция для строк или чисел.

Теперь вызываем:

```cpp
contains(occupiedSeats, 5);                  // T = int
contains(guests, std::string("Аня"));        // T = std::string
```

По типам аргументов компилятор **выводит** `T`, а затем при необходимости создаёт подходящую функцию: `contains<int>` и `contains<std::string>`. Это называется **инстанцированием шаблона** (к нему вернёмся в конце). Тип можно указать явно: `contains<std::string>(guests, "Аня")`. Без явного указания запись `contains(guests, "Аня")` может не пройти: для второго аргумента выводится массив символов, а не `std::string`.

Шаблон не принимает совершенно любые типы автоматически. Функция `contains` требует, чтобы элементы типа `T` можно было сравнивать выражением `value == wanted`. Если такого сравнения нет, при использовании соответствующего `T` компилятор выдаст ошибку.

Это **шаблон функции** (`function template`): тип подставляется в общее описание функции. Вызов конкретной функции после подстановки выглядит и работает как обычный вызов C++.

### Ещё два классических алгоритма

В том же файле расположены `maximum<T>` и `swapValues<T>`. Первая возвращает больший из двух аргументов и потому требует оператора `<`; вторая меняет два объекта местами и требует возможности копирования и присваивания.

```cpp
template <typename T>
void swapValues(T& first, T& second) {
    T temporary = first;
    first = second;
    second = temporary;
}
```

Почему здесь `T&`, а не `T`? При передаче по значению функция обменяла бы только копии, оставив исходные переменные без изменений. `T&` — ссылка на тот же объект, поэтому присваивания меняют аргументы вызывающего кода.

### Почему определения шаблонов находятся в заголовочном файле

Компилятор должен видеть тело шаблона в месте, где создаётся его конкретный вариант. Если оставить в заголовке только объявление, а определение спрятать в отдельно компилируемом `.cpp`, другой файл обычно не сможет инстанцировать новый `T`. Поэтому в этом проекте определения шаблонов лежат в `.hpp`. Это не единственный способ организовать шаблонный код: позднее разберём явное инстанцирование в `.cpp`.
